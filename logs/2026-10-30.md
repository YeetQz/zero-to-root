## 🎯 Goal
Get Kali running in VirtualBox and learn my first nmap scans.

## 🛠️ What I did
- Installed Kali 2026.3 in VirtualBox (Debian 64-bit, 4 GB RAM, 2 CPUs, 128 MB video)
- Fought soft lockups and `rcu_preempt` stalls for hours
- Found the real cause: **Hyper-V / Virtualization-based security** was running under VirtualBox (turtle mode 🐢)
- Fixed it, rebooted, and Kali booted to the login screen in ~30 seconds
- Ran my first nmap scans

## 🐛 What broke (and the fix)
| Problem | Cause | Fix |
|---|---|---|
| `soft lockup - CPU stuck for 34s` | Hyper-V starving the VM | Turned off the hypervisor + VBS (see [lab/hyperv-fix.md](../lab/hyperv-fix.md)) |
| `vmwgfx ... unsupported hypervisor` | Graphics driver warning | Switched controller to VBoxSVGA, 128 MB video |
| `Temporary failure resolving 'http.kali.org'` | No network yet | Fixed after the Hyper-V fix |
| VM engine said `native API` | VirtualBox running on Hyper-V | Now says `VT-x/AMD-V` ✅ |

## 🧠 What I learned
- **nmap 127.0.0.1** → all 1000 ports closed. A fresh Kali runs nothing, which is good.
- Started SSH → port 22 flipped to **open**. Stopped it again after.
- **`-sV`** found the exact version: `OpenSSH 10.4p1 Debian 5`. Versions are what you look up for vulnerabilities.
- **`-A` on scanme.nmap.org** found Apache 2.4.7 and nmap scripts (lines starting with `|_`).
- 🤯 The OS guess said *"VirtualBox Slirp NAT"*, one hop, 0.35 ms. That was VirtualBox's NAT relay, not the real server. **nmap output can lie, so sanity-check it.**
